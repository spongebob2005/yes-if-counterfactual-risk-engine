From no to the cheapest yes.

Four layers on every payment. The detector says how risky it is; the rest decides what to do about it.

01 / DETECT

A score you can trust.

Gradient-boosted trees on causal card history and shared-device signals, calibrated so 0.10 really means about 10%.

LightGBM · isotonic
02 / EXPLAIN

Reasons, not a black box.

Every decision lists the signals that pushed it up or down: a new device, an odd hour, a device shared by many cards.

path contributions
03 / YES, IF

The smallest change.

Searches 83 changes a buyer can actually make (part-payment, delay, debit or credit) and returns the cheapest ones that cross the approval line.

counterfactual search
04 / LEARN

Cheapest friction wins.

A policy that learns how well step-up, hold and block really work from their outcomes, and shifts when attackers start beating one-time passcodes.

Read this before quoting the numbers
  • The model is trained on a synthetic, reproducible transaction generator in the IEEE-CIS column layout (account takeover, card testing, device rings). The IEEE-CIS pipeline is included for anyone with Kaggle access.
  • Step-up, hold and block outcomes are simulated with stated, configurable assumptions: no public dataset records them. A real rollout starts in shadow mode, then an A/B test.
  • Counterfactuals describe the model's decision boundary ("the model would accept this if…"), not causal truth. Buyers only see coarse guidance; exact options are for analysts.
